# ชุด Prompt + บทเรียน: "Lab ADS + PCF Combo" สองชิปบนบัส I2C เดียว (สำหรับผู้เรียน)

ไฟล์นี้คือ **ชุดคำสั่ง (prompt) ภาษาไทย** ไว้ให้ผู้เรียนคัดลอกไปสั่ง AI ผู้ช่วยเขียนโค้ด (เช่น Claude Code ใน VS Code)
ให้สร้างระบบแบบเดียวกับ branch `feature/ads-pcf-combo` **ทีละขั้น** พร้อมความรู้ที่ควรได้ในแต่ละขั้น

จุดเริ่ม: branch `feature/ads1115-analog` (แล็บ ADS ที่ทำเสร็จแล้ว) + ไฟล์ HAL/UI จาก `feature/pcf8574-io` (แล็บ PCF ที่ทำเสร็จแล้ว)
ระบบที่จะได้: ADS1115 (ADC 4 ช่อง) + PCF8574 (I/O 8 ขา) บนสาย SDA/SCL คู่เดียว ให้ค่าแอนะล็อกสั่งขาดิจิทัล และปุ่มสั่งค่าตั้งของ ADC
มี 6 แท็บ: รวม | ADC | I/O | กฎ | บัส | ระบบ (Calibration อยู่ใน ระบบ > สัมผัส ตามกติกาของคอร์ส)

> **หลักสำคัญ:** สั่งทีละขั้น → build → upload → ทดสอบบนบอร์ดจริง → ผ่านแล้วค่อย commit แล้วจึงไปขั้นถัดไป

## 0. เตรียมตัว

| อุปกรณ์ | หมายเหตุ |
|---|---|
| CYD (ESP32-2432S028) | env `cyd` (ILI9341) หรือ `cyd_st7789` |
| โมดูล ADS1115 (หรือ ADS1015) | ADDR ลง GND = 0x48 |
| โมดูล PCF8574 สีน้ำเงิน | A0-A2 ลง GND = 0x20 |
| LED 4 ดวง + R 330Ω, ปุ่มกด 4 ตัว | LED แบบ sink ที่ P0-P3, ปุ่มลง GND ที่ P4-P7 |
| โพเทนชิโอมิเตอร์ 10k | ที่ A0 ของ ADS |
| ตัวต้านทาน 10 kΩ | pull-up ของ IO35 (ถ้าจะใช้ INT/ALRT) |

ต่อ SDA (IO27), SCL (IO22), 3.3V, GND ของทั้งสองโมดูล **ขนานกัน** ดูผังเต็มใน README หัวข้อ 2

**ความรู้ก่อนเริ่ม**
- I2C แยกอุปกรณ์ด้วย address: ADS 0x48-0x4B, PCF 0x20-0x27 (PCF8574A 0x38-0x3F) → ไม่ชนกัน ต่อร่วมกันได้
- บัสร่วมต้องวิ่งที่ความเร็วของตัวที่ช้าที่สุด: PCF8574 = **100 kHz** ตาม datasheet (ADS ได้ 400 kHz)
- INT ของ PCF และ ALRT ของ ADS เป็น **open-drain** = ดึงลงได้อย่างเดียว ต่อรวมสายเดียวได้ (wired-OR) แต่ต้องมี pull-up 1 ตัว

## ขั้น 2: บัสร่วม

```text
ตอนนี้ ADS มี task ของตัวเองบน core 0 ส่วน PCF อ่านใน loop() บน core 1 ทั้งคู่เรียก Wire เอง
ช่วยทำ hal_bus.cpp:
- Wire.begin ที่เดียว (SDA 27, SCL 22, 100 kHz) และ recursive mutex ตัวเดียว ห่อด้วย struct BusGuard
- busWrite(addr, data, n) / busRead(addr, data, n) ที่ถือ BusGuard
- task "i2c" บน core 0 วน: adsService(now) -> pcfService(now) -> rulesService(now) แล้วหลับไม่เกิน 5 ms
- แก้ hal_ads.cpp และ hal_pcf8574.cpp ให้ใช้ busWrite/busRead และ BusGuard แทน Wire/mutex เดิม
- ADS: ระหว่างรอแปลง ถ้ายังไม่ถึงเวลาแปลงเสร็จ ห้ามถามชิป ให้หลับจนถึงเวลา
ทดสอบด้วยคำสั่ง Serial b ให้พิมพ์จำนวนธุรกรรมต่อวินาทีแยกชิป
```

**ความรู้:** `Wire` ของ ESP32 ใช้ได้ทีละงาน สอง task เรียกพร้อมกัน = ไบต์ของสองธุรกรรมพันกัน
ทางแก้มี 2 แบบ: (1) mutex ทุกจุดที่แตะบัส (2) ให้ task เดียวเป็นเจ้าของบัส แล็บนี้ใช้ทั้งสองอย่าง (task เดียว + mutex เผื่อ UI สั่งตรง)

**ตัวเลขจริง:** ก่อนใส่ "ห้ามถามก่อนเวลา" ADS ใช้ ~12 ธุรกรรมต่อค่า 1 ค่า (บัสไม่ว่าง 41%) หลังใส่เหลือ ~5 (18%) ได้ค่าเท่าเดิม

## ขั้น 4: INT ร่วม

```text
INT ของ PCF8574 และ ALRT/RDY ของ ADS1115 ต่อรวมกันที่ IO35 (pull-up 10k ภายนอก)
- ADS โหมด RDY: เห็น IO35 เป็น LOW แล้วยังไม่อ่านผล ให้อ่านบิต OS ยืนยันก่อนเสมอ (อาจเป็น PCF ที่ดึง)
  อ่านผลแล้วเริ่มแปลงครั้งต่อไปทันที ให้ขากลับเป็น HIGH
- PCF โหมด INT: ไม่ใช้ attachInterrupt (ADS ก็สร้างขอบขาลง) ให้ดูระดับขาในทุกรอบของ task i2c: LOW = อ่านพอร์ต
- ถ้า LOW ค้างเกิน 1 วินาทีทั้งที่อ่านแล้ว (ไม่มี pull-up) ให้นับเป็น "INT ค้าง" และถอยไปอ่านทุก 20 ms
แสดงระดับ IO35 ในคำสั่ง b
```

**ความรู้:** wired-OR บอกได้แค่ "มีใครสักตัวเรียก" ไม่บอกว่าใคร → ต้องถามทุกตัวที่ต่ออยู่ (ระบบ interrupt แบบแชร์ของ PC ก็ทำแบบนี้)

## ขั้น 5: กฎข้ามชิป

```text
ทำ hal_rules.cpp: กฎ 8 ข้อ แต่ละข้อมี en, slot (A0-A3 / A0-A1 / A2-A3), above (> หรือ <), thr, hyst, holdMs, pin (P0-P7), act (ติด/ดับ/กะพริบ/สลับ)
- ฮิสเทอรีซิส: เริ่มทำงานที่ thr แต่เลิกทำงานที่ thr - hyst (ถ้า >) หรือ thr + hyst (ถ้า <)
- holdMs: เงื่อนไขต้องค้างนานเท่านี้ก่อนเปลี่ยนสถานะ
- หลายกฎบนขาเดียว: กฎหลังทับกฎก่อน
- ผู้ใช้แตะขาที่กฎคุม = manual จนกว่ากฎนั้นจะเปลี่ยนสถานะ
- เขียน PCF เฉพาะเมื่อไบต์เปลี่ยน, บันทึก NVS key rules, คำสั่ง Serial #rule และ u
ค่าเริ่มต้น: A0 > 1.65 V -> P0 ติด, A0 > 2.8 V -> P1 กะพริบ
```

ลองเอง: หมุนโพเทนชิโอช้าๆ รอบ 1.65 V ตั้ง hyst = 0 แล้ว 0.1 ต่างกันอย่างไร?

## ขั้น 7: หน้าจอ + ภาพเคลื่อนไหว

ออกแบบก่อนเขียนโค้ด (mockup 320x240 ภาษาไทยจริง) แล้วค่อยสั่ง:

```text
ทำแท็บ รวม | ADC | I/O | กฎ | บัส | ระบบ ตามแบบที่อนุมัติ (font_th_16/24, ไม่มีเงา, ปุ่มสูง >= 30 px)
ภาพเคลื่อนไหวใช้ lv_anim เท่านั้น ห้ามใช้ shadow:

- ui_flash: สีพื้นจากส้มกลับเป็นสีการ์ด เมื่อกฎเริ่มทำงาน
- ui_bar_anim: lv_bar เลื่อนไปค่าใหม่ใน 220 ms
```

## ขั้น 8: RAM ไม่พอ

สร้างทุกหน้าพร้อมกันแล้วบอร์ดรีบูตวนตอนสร้างแท็บบัส (heap หมด) prompt ที่ใช้แก้:

```text
บอร์ด abort() ใน lv_obj_allocate_spec_attr ตอนสร้างแท็บที่ 5 log บอกว่าแต่ละแท็บกิน 50-60 KB
ช่วยทำแบบ "สร้างเมื่อเปิดดู / ลบเมื่อออก" สำหรับส่วนย่อยของแท็บ ADC, กฎ, ระบบ:
- ลบ widget เก่าด้วย lv_obj_del_async (อาจถูกเรียกจาก event ของ widget นั้นเอง)
- ลบ lv_timer ของหน้าเก่าก่อน (หน้าแล็บ ADS เพิ่มฟังก์ชัน close, แท็บระบบจดตัวจับเวลาที่เกิดระหว่างสร้างแล้วลบทิ้ง)
- ฟังก์ชัน refresh ที่ถูกเรียกจากที่อื่นต้องเช็กก่อนว่าหน้านั้นสร้างอยู่
- หน้าตั้งขา PCF ทำเป็นหน้าเต็มจอที่สร้างเมื่อเปิด
log heap8 (heap_caps_get_free_size(MALLOC_CAP_8BIT)) ของทุกการสร้าง
```

**ความรู้:** `ESP.getFreeHeap()` นับรวม RAM ที่ `malloc` ใช้ไม่ได้ ให้ดู `heap_caps_get_free_size(MALLOC_CAP_8BIT)` และก้อนใหญ่สุดแทน
